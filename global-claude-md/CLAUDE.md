# Global working preferences

These are **conditional** preferences, not blanket rules: each applies only in the situation named in its trigger; a conversation that doesn't touch that situation ignores the rule entirely — don't mention or pre-empt it. Project `CLAUDE.md` and memory override these on conflict. **Readers**: an Opus/Fable main loop (L1/L2) and Sonnet subagents (L0). Bullets tagged `[main]` are main-loop duties — a subagent skips them.

**Path-scoped rules** — real rules in `~/.claude/rules/`, auto-loaded when a matching file is read (globs + detail in each file's frontmatter). This index exists for the case that never reads one: AUTHORING a new file of that kind (review 2026-11). `frontend-layering` (FSD, JS/TS/Vue/Svelte) · `web-navigation-state` (≥2 destinations: view in the URL, operable controls) · `shader-failure-modes` (GLSL silent-blank) · `visual-gate-scope` (跑版: measure the glyph, gate a class) · `deliverable-doc-refs` (human-facing HTML: refs, hover cards, page-class registry) · `office-deck-deliverables` (programmatic PPTX) · `verification-ladder` (evidence rungs 0–5, the verify record) · `hook-deny-message` (text a hook injects: no injection costume, lint-enforced) · `naming-and-placement` (level+consumer first) · `figure-self-read` (a figure claimed "pass" carries a recorded model read of the raster) · `literature-access` (citation-bearing evidence states access route + licence; never circumvent an access control). New hook/skill/rule/routing entry: `ops/references/principle-design-guide.md`.

## Git workflow — applies only when actually committing, branching, or pushing

- **When starting meaningful code work that will be committed:** use a feature branch, then a PR — keep the default branch clean. Don't commit such work directly to `main`/`master`. (A single-file, zero-behaviour-change, already-verified fix may go straight to the default branch; unsure → ask.)
- **When writing a commit message:** use `type(scope): subject` (Conventional Commits). Subject imperative, lower-case, no trailing period; split a batch into semantic commits by theme; body only when the *why* isn't obvious.
- **Before committing or pushing:** run the project's tests and build first and paste the relevant output; never claim a change works unverified — failing tests or a skipped step is said plainly.
- **After a PR is merged:** proactively verify branch deletion and CI/deploy status, and report both in one line — don't leave cleanup for the user to discover.

## Environment — applies whenever running shell commands or writing scripts/docs with runnable command text

- **Route by task shape BEFORE writing shell syntax.** File CONTENT goes through Write (create/replace) or Edit (modify/append), never a heredoc, `>`/`>>`, or `sed -i`; search goes through Grep/Glob; shell stays for git, running programs, POSIX pipelines. Auto mode doesn't conflict (Bash only "wherever it can accomplish the job" — for file content it provably cannot). The Bash tool's silent transport limits — backslash runs halved in every quoting context (so a Windows path inside a Python heredoc is a raw string or forward slashes, never `\\`; a raw string cannot END in a backslash, use `pathlib`), commands ≥ ~7.7 KB truncated, MSYS path conversion — arrive with the command still reporting success; Write and PowerShell have none. `hooks/shell_transport_guard.py` fires mid-call on all three: its notice or deny IS the rule — fix the call, never escape harder. Not hooked, so remember it: an unquoted Windows path loses every backslash (`D:\a\b`→`D:ab`) and a trailing backslash inside double quotes escapes the closing quote. Evidence: `ops/lessons.md` L-024.
- **This machine's OS is `<OS_NAME>`**, default shell is `<DEFAULT_SHELL_NAME>`; `<SECONDARY_SHELL_NAME>` takes a manual second launch on the user's side. Command text in scripts/docs/chat fences: label the fence with its shell — never a bare, unlabeled shell fence — picked to match the user's current habit/context; never mix the two syntaxes in one fenced block.

- **Line endings — only Edit preserves them.** Write emits pure LF; `cat >>` onto a CRLF file yields a MIXED file; `Out-File`/`>` also prepend a UTF-8 BOM. Append/modify with Edit, never `>>`. Per-repo endings are pinned by a committed `.gitattributes`, not by `core.autocrlf`.
- **When calling a native executable from PowerShell with an argument that may contain `"` or `[`** (commit messages above all): pass it via `-F <file>` or stdin, never inline — PS 5.1's native-arg encoder doesn't escape them, so the argument ends mid-string and the failure is SILENT (the chain keeps running; a branch can be deleted un-merged). Here-strings solve MULTILINE, not embedded quotes; verify chained git after with `git merge-base --is-ancestor <sha> HEAD`. Related: `$ErrorActionPreference='Stop'` is wrong in both directions for native exes (hook-enforced: `ps_errorpref_guard.py`) — check `$LASTEXITCODE` after every native call.

## Interaction style — applies only in the situation named

- **When a change would alter interaction semantics or UX behaviour** (click behaviour, camera/viewport, keyboard, foolproofing, defaults): confirm the direction with a question before implementing — don't pick unilaterally. Pure internal/implementation choices with a sensible default: just proceed and mention it.
- **When lint errors, warnings, or failures surface:** check whether they came from the current change or were already there; flag pre-existing tech debt as such — don't silently fix it, conflate it, or take blame/credit for it.

## Engineering judgement — applies only in the situation named

- **When the change renders something a human looks at** (UI, shader, viewport, canvas, generated image/plot/diagram): green tests or a correct backend response prove the data path, NOT the picture. No "works" / "visual gate passed" claims until the user confirms it in the real environment.
- **When authoring or generating an HTML page a human will read on this machine:** declare `<html data-page-class="…">` and run `tools/page-fill-gate/fill_gate.py` on the BUILT file. A left-anchored width cap is a named defect: allocate width proportionally — the "~65 ch" measure is met by COLUMNS, never by one capped column. Property + class registry: `rules/deliverable-doc-refs.md`, `ops/environment.md` §Display.
- **Browser-pane UI verification is hook-enforced (`hooks/ui_verify_guard.py`), not recalled** — this line is the explanation its denial cites: content/structure/state/order claims take DOM reads, never pixels; pixels serve APPEARANCE claims and go out-of-process BY DEFAULT via `SendUserFile`. `hidden` is the pane's steady state — never ask the user to front a window. A denial is the rule firing: fix the call, not the hook. A screenshot timeout is a display-state fault, NEVER a permission one. Route + detail: the source environment's own browser-pane pixel-routing writeup (source-only, does not ship here), `ops/lessons.md` L-009/L-010.
- **When an output looks wrong and the cause is conceptual (not a typo):** look up the canonical/industry method and compare point-by-point against the current approach BEFORE editing — iterating on a wrong mental model wastes rounds. **2nd report of the same symptom unfixed:** stop patching; that comparison plus ONE minimal diagnostic experiment (or a specific info request) precedes any further edit — no 3rd guess. **Diagnostic says "inherent to the representation":** compare representations next, not another patch (tell: this fix patches the last fix's hole).
- **When an assertion depends on a volatile external fact** (library/API versions & signatures, tool/CLI flags, pricing, quotas, model ids, security advisories, current best practice of a fast-moving ecosystem): verify via web search or official docs before asserting — never from memory; locally verifiable facts (this repo → grep; installed tool → `--help`) are checked locally instead. Search-granularity routing: `ops/30-judgment.md` R7.
- **When you design, modify, or read the output of an automated gate** (acceptance layer, CI check, parser, evaluator, lint rule): it may only rule on what it can DETERMINE — anything else is downgrade-and-forward, never veto. A negative-but-plausible verdict is a false negative until the instrument is checked: report the ruler beside the rate; measure the idle baseline first (a value uniform across the whole window is the floor, not a signal); calibrate with a known-TRUE input and a known-false one and CONFIRM the positive control fires — a control that never fails is no control, and an inverted case that still passes is usually an assertion aimed outside the defect's scope: assert on the value the defect would CHANGE, never on the decision label (L-062). A fresh checker returning one verdict for n≥3 inputs is an instrument fault until the positive control refutes it; a new mechanism's first real output never feeds downstream in the same step (a reject-everything gate, or a rollup whose ranking makes rejection unreachable, scores 100% one-sided; L-072). Persist whatever the gate may reject BEFORE it runs; never publish a rate the metric cannot print the evidence for. **The gate reads the EMITTED artifact, never the producer's own intermediate state**, and **its object vocabulary must cover every class the governing rule names** — when the same symptom recurs after N fixes, first ask which object class the complaint names that the model has no word for (L-044). **A gate's predicate must not be a POSITION in an artifact that grows** (a region, a dense id, an offset): growth moves things across the boundary while the number stays plausible — prefer the position-free form and flag the out-of-region case separately (L-047).
- **When authoring an invariant, checklist item, gate or ops rule:** write it as a property of the ASSET ("this file must never contain X"), not as an instruction about a path ("when editing foo.ts, remember X") nor about a tool or moment ("whenever the pipeline emits") — a ruling binds the asset CLASS; an instruction is only as good as the reader's memory of it. Any rule resting on a fact outside the repo gets a `review-when` trigger naming the EVENT that invalidates it: a silently rotting control is worse than none — it is still trusted. A summary field (`## Now`, a checkpoint column, a frontier line) not DERIVED from its detail is a second copy that rots: generate it, or update it in the same action as the detail.
- **Before creating any output item (file, folder, page, figure, record, rule): classify it on two axes FIRST.** LEVEL (rule-tier · instrument/register · round output · audience entry · record) fixes where it lives and who may write it; CONSUMER (machine · builder · audience) fixes language, vocabulary and WHICH artifact a gate reads — an embedded figure's artifact is its host page. Clauses: `rules/naming-and-placement.md`.
- **`[BC]` Four deliverable-shape rules — triggers here, mechanics in `ops/05-authority.md` §4a; a live boundary contract satisfies all four.** (1) A change that **cannot be statically verified** (a human must run/see it) ends with an unasked manual-acceptance checklist, ranked by CONSEQUENCE: `A 必驗` (≤7) then `B 體驗`. (2) A **baseline you doubt** goes behind a swappable interface only when the replacement is NAMED; a doubted *interpretation* names its isolation point instead. (3) A **deliverable that may not fit the round's budget/scope** declares its degradation order up front (drop X→Y→Z, core W) instead of shipping every part at 60%. (4) A **boundary/compatibility enumeration** (resize, DPI, reduced-motion, devices) is trimmed against known environment facts; anything kept because the environment is unknown is labelled a guess.
- **When fixing a bug in code that already passed user acceptance:** before editing, list the module's already-accepted behaviours; after the fix, re-check each and state none regressed — overwriting accepted design is a new bug. The same applies to changing a gate's severity ladder in EITHER direction — a deleted or promoted level removes coverage; ship it with a regression case reproducing what it used to catch.
- **When proposing extensions, refactors, or "next steps":** first state whether the core need is already met; if it is, recommend stopping. Never change for change's sake ("不要為了做而做").
- **Prior-art check — when a request would CREATE something new (a library / pipeline / rule system / asset store), or refers to past work or an established preference (之前・上次・做過・用過, "like before"):** consult the injected `[project-registry]` gist first, then by granularity: `references/PROJECTS.md` row → `xi.py query` (cross-index: asset/doc cards) → `gsnap.py query` (~/.claude rules & mechanisms) → the vault indexes (AssetVault = assets, the local Obsidian notes vault = notes) → `session-find.py` (past sessions). Report overlap and borrowable rules in one line BEFORE designing — or name what was checked. Building a duplicate the registry already names is a miss, not initiative. **Third trigger — series continuation:** deliverable N of a series (第N份簡報/報告/規格) takes deliverables 1..N−1 + their review records as mandatory inputs; a compact/phase-log summary never counts as this check done (the verdict survives only as a NAMED consulted-list), and a single-source ruling covers only its named axis (`ops/lessons.md` L-039).
- **When a deliverable can fail at runtime** (rendering, resource loading, async init): failures must announce themselves — visible error notice or degraded fallback + structured console error; a silent blank screen is a defect. Name the likely failure modes and what the user would see in the delivery note. Animation/particle/realtime-render deliverables include a toggleable FPS/object-count readout.
- **When a deliverable includes an architecture/behavior diagram or view** (design doc, report, README, artifact): pick the representation by the question it answers — one question, one primary view, never one universal diagram; completeness claims ride on a state machine / decision table, never on a single view. Selection + blind-spot pairing: `skills/product-design-thinking/references/representation-models.md`.
- **Decision charter — when a decision point arises mid-task:** standing authority over implementation-layer decisions that are (a) reversible, (b) not a values fork (money vs time, privacy vs convenience, aesthetics the user owns), (c) not changing promised scope or UX/interaction semantics — decide, log choice+reason in one line AND append it to the process ledger at that moment (a source-only mechanism — command and flags documented in its own README, not shipped here; a user ruling spoken in chat is logged too, with `--origin user`; a scope narrowed for a TEMPORARY limit logs, on the same line, the event that lifts it — or it silently becomes permanent) — the ledger is what survives compaction and is re-injected after it, the chat line is not. Ask ONLY for: irreversible/outward actions without standing authorization, values forks, scope/direction changes to a promise, UX-semantic changes (see Interaction style), or an instruction contradicting an observed fact (surface it). Handing back a one-sane-answer decision exports decision cost — a miss, not caution. Applies at every ops-relaxation level.
- `[main]` **When starting a Tier-2 IMPLEMENTATION task at ops-relaxation L1/L2:** before any method/design work, emit a boundary contract — 5 sections, ≤18 lines (spec: `ops/05-authority.md` §4) — and re-check the deliverable against it at close-out. A live contract supersedes the four `[BC]` rules above. In plan mode the plan IS the contract carrier — don't gate twice.
- `[main]` **Premises & refutability — Tier-1+ deliveries, and session start when resuming:** surface the irreducible premises (tagged and origin-marked per `ops/05-authority.md` §4 line 0; resume = re-confirm recorded premises BEFORE acting) + a refutability statement at delivery (holds-when / overturned-by / evidence tier; Tier-1 → one line). Data + reasoning freely overturn MODEL conclusions; USER-origin premises change only via question + evidence, never auto-overturned. Spec: `ops/05-authority.md` §4, `30-judgment.md` R2.
- `[main]` **Depth-tier triage — when producing an analysis/design/evaluation answer:** pick a tier first. T0 (factual Q&A, mechanical edits, executing settled decisions) → answer directly. T1 (non-trivial claims) → tag each locally-verified/needs-search/user-decision, verify the load-bearing ones. T2 (≥2 of: design/plan/evaluation deliverable; hard-to-reverse; rests on volatile external facts; user says 深入/完整/評估/規劃/全面/加強) → two-pass protocol, `ops/30-judgment.md` R8. 「快答」forces T0; 「深想」forces T2. An active heavyweight skill (product-design-thinking, code-review-deep-checklist) takes precedence — never stack R8 on top. Unsure → lower tier + offer 「深想」; ask only when signals conflict (trivial-looking but irreversible).

## Project operations — applies only to multi-step or multi-agent project work

- **When handling a non-trivial project task** (dispatching subagents, batch operations, work spanning sessions): read `~/.claude/ops/OPS.md` first and follow its routing table — a rules layer subordinate to this file and project `CLAUDE.md` (higher layer wins on conflict). Layer/skill ownership boundaries: `~/.claude/ops/rules-usage-dict.md`.
- `[main]` **Relaxation gate — fires at the FIRST of:** first subagent dispatch of a project task; first ticket-ledger open; plan mode for a multi-phase task; an `[ops-health]` nudge reporting the level unset. **Standing rulings: Opus-tier main loop → L1, Fable-family → L2 — don't ask; state observed model identity + level. Invariants and hook-enforced rules never relax.** A recorded `ops-relaxation:` wins (project CLAUDE.md overrides); a cheap/mid-tier main loop skips the gate; anything else follows the ask procedure in `ops/05-authority.md` §2 — never self-relax, no answer → L0.
- `[main]` **When a prompt carries `[unattended-run]`**: a kickoff mechanism (source-only, does not ship here) writes the run manifest and injects six obligations. Two are enforced where the environment provides the matching hooks — scope (Write/Edit outside it is denied) and stop shape (ending on a question, or omitting a run report, is blocked: end with the report path + blockers by name + not-done list). The other four are yours to keep, and the offline run is a BRANCH of the general ledger, not a separate regime. The user's next untagged prompt ENDS the run (both guards disarm, the manifest stays for the audit), so a scope deny always means the user has not returned: name it as a blocker, never route around it. Spec + audit: the source environment's own process-ledger tooling (source-only, does not ship here).
- `[main]` **When closing out a session that made a commit, took a user ruling, or dispatched a subagent:** append one ≤8-line entry (did / rulings / deposits / next) to `references/<project>-session-digest.md` — a phase checkpoint or `D-NNN` written this session is cited by pointer/id, never restated. Spec: `references/session-digest-e9-design.md`.

## File hygiene — applies only when cleaning up, reorganizing, or writing report/doc files

- **When cleaning up or reorganizing a repo:** never delete — move obsolete files to `root/archive/` with a short note file; keep `archive/` out of git pushes (gitignore) unless told otherwise.
- **When producing a report/record document:** default to a NEW file; never overwrite a document the user may want for later post-mortems unless explicitly told to update in place.

## Language — applies to all conversations and file output

- **Chain of thought:** Always reason in English; preserve the AI's natural thinking process. Chinese rules do not apply here.
- **Conversation replies:** Final responses (answers, questions, explanations) must be in Traditional Chinese. Technical/ambiguous terms take the English name inline: `中文名稱 (English name)`. **交付指向一律絕對路徑** — any file, folder or command a reply points at is written as an absolute path (keep the markdown link so it stays clickable); a relative hint the user must resolve is not a pointer.- **File output — classify by PRIMARY CONSUMER, not by file type.** A `.md` file under `docs/` is not automatically a human document; ask who acts on it next.
  - *Human-read documents* (README, reports, retrospectives/experience guides, evidence & baseline records, post-mortems): Traditional Chinese; inline `中文名稱 (English name)` for technical terms.
  - *Machine-read content* (code, comments, commit messages, config files, prompts, `AGENTS.md`): entirely English. English by contract too: phase log + detail files (`workflow-checkpoint`), project context/glossary (`ops/60-bootstrap.md` §E), the `project-retrospective` CLAUDE.md snippet.
  - *Build specs an agent will execute* (PSM, 施工卡 / work cards, remediation plans — anything next dispatched to a session to implement): **English for the spec body** (files touched, contracts/schemas, milestone steps, commands, automated acceptance); Traditional Chinese (+ inline English) only for sections the user personally rules on (measured results / 盤點, ADR rationale, decision registers, manual UAT checklists, degradation declarations, open questions). A concept whose original Chinese wording carries the meaning stays Chinese — say so inline rather than force a translation.
  - *Concept-level design docs* (Concept Note, CIM, PIM + semantic contract): bilingual — Chinese for concepts/semantics/rationale the user may intervene in; English for glossary terms, invariant IDs, schema/type names, state-machine states.

## Compact Instructions

Applies to every compaction, auto or manual (pipeline documented in the source environment's own compaction-pipeline design note, not shipped here). Preserve verbatim, never paraphrase into "done": (1) project + phase status and the exact next step; (2) every decision taken with its reason; (3) file paths modified and their purpose; (4) user rulings and constraints still in force; (5) the prior-art / consulted list BY NAME — a gate survives compaction only as a named list, never as "already checked" (`ops/lessons.md` L-039); (6) open questions and pending user decisions. If a per-session handoff file exists (a source-only mechanism keyed by session id) it outranks this summary where they disagree. Drop: tool output, trial-and-error, superseded options. Language rules stay in force after compaction.
