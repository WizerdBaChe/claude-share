# Global working preferences

These are **conditional** preferences, not blanket rules: each applies only in the situation named in its trigger; a conversation that doesn't touch that situation ignores the rule entirely — don't mention or pre-empt it. Project `CLAUDE.md` and memory override these on conflict. **Readers**: an Opus/Fable main loop (L1/L2) and Sonnet subagents (L0). Bullets tagged `[main]` are main-loop duties — a subagent skips them.

**Path-scoped rules** — real rules in `~/.claude/rules/` (globs + detail in each frontmatter), auto-loaded when a matching file is read or (2.1.288+) written. Before AUTHORING a new file of a kind, read its rule first — the names say the kind (review-when: `rules/` gains or loses a file): `frontend-layering` · `web-navigation-state` · `visual-gate-scope` · `deliverable-doc-refs` · `office-deck-deliverables` · `verification-ladder` · `hook-deny-message` · `naming-and-placement` · `figure-self-read` · `layout-convergence` · `literature-access` · `native-render-first` · `source-quotation-evidence` · `android-device-states` (two further source rules, `explainer-deliverables` and `decision-sheet`, are not shipped in this share). New hook/skill/rule/routing entry: `ops/references/principle-design-guide.md`.

## Git workflow — applies whenever work lands on disk (new folder, file changed, commit, branch, push)

- **When creating a new project folder or a key folder** (anything more than one session will write into): `git init` it in the same step, commit the scaffold, pin endings with `.gitattributes` by consumer (CRLF: human-read, Windows scripts; LF: machine-read); no remote unless asked. A work folder without a repo is a defect to name, never a default (user ruling 2026-09-17).
- **Commit cadence — standing authorization, never ask (user ruling 2026-09-17):** every time an item LANDS — a file/feature/record finished, a phase closes, a gate passes, or just before a risky edit — commit it; never end a turn with finished work uncommitted. The point is a rollback point. Stage by path (`git add <paths>`, never `-A`); obey the tree-conflict rules — `ops/references/shared-tree-git.md` §1/§1a (worktree pool, peer provenance, `git reflog -3` glance), the branch-commit and worktree-scope hooks — a hook deny is the rule firing, not a reason to skip the commit. PUSH still asks, except inside 「收掉」 (After-merge bullet).
- **When starting meaningful code work:** use a feature branch, then a PR (no remote → local ff-merge) — keep the default branch clean. Don't commit such work directly to `main`/`master`. (A single-file, zero-behaviour-change, already-verified fix may go straight to the default branch; unsure → ask.)
- **When writing a commit message:** use `type(scope): subject` (Conventional Commits). Subject imperative, lower-case, no trailing period; split a batch into semantic commits by theme; body only when the *why* isn't obvious. A checkpoint commit whose verification is incomplete says so in the subject (`wip(scope): …`).
- **Before merging to the default branch or pushing:** run the project's tests and build first and paste the relevant output; never claim a change works unverified — failing tests or a skipped step is said plainly.
- **When the user says 「收掉」/「收工」 (ruling 2026-09-21), and after any PR merge:** 收掉 = drive the WHOLE chain to done without re-asking — push → PR → merge → tag/release (if the project releases) → verify branch deletion + CI/deploy → checkpoint/digest — then report in one line. It authorizes push for that chain; failing tests/build or a hook deny still stops it, said plainly. A half-done chain handed back is a miss.

## Environment — applies whenever running shell commands or writing scripts/docs with runnable command text

- **Route by task shape BEFORE writing shell syntax.** File CONTENT goes through Write (create/replace) or Edit (modify/append), never a heredoc, `>`/`>>`, or `sed -i`; search goes through Grep/Glob; shell stays for git, running programs, POSIX pipelines. The Bash tool's silent transport limits — backslash runs halved in every quoting context (a Windows path in a heredoc: raw string or forward slashes, never `\\`), commands ≥ ~7.7 KB truncated, MSYS path conversion — arrive with the command still reporting success; Write and PowerShell have none. `hooks/shell_transport_guard.py` fires mid-call on all three and denies an unquoted Windows path (`D:\a\b`→`D:ab`): its notice or deny IS the rule — fix the call, never escape harder. Not hooked, so remember it: a trailing backslash inside double quotes escapes the closing quote. `/tmp` in Git Bash and `/tmp` in a native Python process are DIFFERENT folders — hand files between steps only by the scratchpad's absolute path (L-094). Why (auto mode included) + evidence: `ops/rule-registry.md` shell tool routing, L-024.
- **This machine's OS is `<OS_NAME>`**, default shell is `<DEFAULT_SHELL_NAME>`; `<SECONDARY_SHELL_NAME>` takes a manual second launch on the user's side. Command text in scripts/docs/chat fences: label the fence with its shell — never a bare, unlabeled shell fence — picked to match the user's current habit/context; never mix the two syntaxes in one fenced block.

- **Line endings — only Edit preserves them.** Write emits pure LF; `cat >>` onto a CRLF file yields a MIXED file; `Out-File`/`>` also prepend a UTF-8 BOM. Append/modify with Edit, never `>>`. Per-repo endings are pinned by a committed `.gitattributes`, not by `core.autocrlf`; `~/.claude` realigns them post-commit (`tools/eol-sync`).
- **When calling a native executable from PowerShell with an argument that may contain `"` or `[`** (commit messages above all): pass it via `-F <file>` or stdin, never inline — PS 5.1's native-arg encoder doesn't escape them, so the argument ends mid-string and the failure is SILENT (the chain keeps running; a branch can be deleted un-merged). Here-strings solve MULTILINE, not embedded quotes; verify chained git after with `git merge-base --is-ancestor <sha> HEAD`. Related: `$ErrorActionPreference='Stop'` is wrong in both directions for native exes (hook-enforced: `ps_errorpref_guard.py`) — check `$LASTEXITCODE` after every native call.

## Interaction style — applies only in the situation named

- **When a change would alter interaction semantics or UX behaviour** (click behaviour, camera/viewport, keyboard, foolproofing, defaults): confirm the direction with a question before implementing. Pure internal/implementation choices with a sensible default: just proceed and mention it.
- **When lint errors, warnings, or failures surface:** check whether they came from the current change or were already there; flag pre-existing tech debt as such — don't silently fix it, conflate it, or take blame/credit for it. A warning that fired or that you overrode gets its own sentence at a reply edge, not a clause in another point; a `standing` `[system-hmi]` alarm is named once at an edge of the first reply.

## Engineering judgement — applies only in the situation named

- **When the change renders something a human looks at** (UI, shader, viewport, canvas, generated image/plot/diagram): green tests or a correct backend response prove the data path, NOT the picture. No "works" / "visual gate passed" claims until the user confirms it in the real environment.
- **When authoring or generating an HTML page a human will read on this machine:** declare `<html data-page-class="…">` and run `tools/page-fill-gate/fill_gate.py` on the BUILT file. A left-anchored width cap is a named defect: allocate width proportionally — the "~65 ch" measure is met by COLUMNS, never by one capped column. Property + class registry: `rules/deliverable-doc-refs.md`, `ops/environment.md` §Display.
- **Browser-pane UI verification is hook-enforced (`hooks/ui_verify_guard.py`), not recalled** — this line is the explanation its denial cites: content/structure/state/order claims take DOM reads, never pixels; pixels serve APPEARANCE claims and go out-of-process BY DEFAULT via `SendUserFile`. `hidden` is the pane's steady state — never ask the user to front a window. A denial is the rule firing: fix the call, not the hook. A screenshot timeout is a display-state fault, NEVER a permission one. Route + detail + incidents: the source environment's own browser-pane pixel-routing writeup (source-only, does not ship here).
- **When an output looks wrong and the cause is conceptual (not a typo):** look up the canonical/industry method and compare point-by-point against the current approach BEFORE editing. **2nd report of the same symptom unfixed:** stop patching; that comparison plus ONE minimal diagnostic experiment (or a specific info request) precedes any further edit — no 3rd guess. **Diagnostic says "inherent to the representation":** compare representations next, not another patch (tell: this fix patches the last fix's hole).
- **When an assertion depends on a volatile external fact** (library/API versions & signatures, tool/CLI flags, pricing, quotas, model ids, security advisories, current best practice of a fast-moving ecosystem): verify via web search or official docs before asserting — never from memory; locally verifiable facts (this repo → grep; installed tool → `--help`) are checked locally instead. Search-granularity routing: `ops/30-judgment.md` R7. **Existing work OUTSIDE this machine** (repos, models/LoRAs, practitioner threads — Reddit, HN, Stack Exchange, forums) goes through a source-only external-search command (does not ship here; query by 2-4 keywords) first (WebFetch/WebSearch cannot reach Reddit); 「盡可能多搜尋」or similar → `--wide`; a leg it marks unavailable was not asked, never "no discussion". Papers stay with `literature-search-extract`.
- **When you design, modify, or read the output of an automated gate** (acceptance layer, CI check, parser, evaluator, lint rule): it may only rule on what it can DETERMINE — anything else is downgrade-and-forward, never veto. Calibrate with a known-TRUE and a known-false input and CONFIRM the positive control fires; assert on the value the defect would CHANGE, never on the decision label; a new mechanism's first real output never feeds downstream in the same step; persist what the gate may reject BEFORE it runs. Remaining clauses (instrument checks, emitted-artifact reads, position-free predicates, rate publication) + incidents: `ops/references/gate-design.md`.
- **When authoring an invariant, checklist item, gate or ops rule:** write it as a property of the ASSET ("this file must never contain X"), not as an instruction about a path ("when editing foo.ts, remember X") nor about a tool or moment ("whenever the pipeline emits") — a ruling binds the asset CLASS; an instruction is only as good as the reader's memory of it. Any rule resting on a fact outside the repo gets a `review-when` trigger naming the EVENT that invalidates it: a silently rotting control is worse than none — it is still trusted. A summary field (`## Now`, a checkpoint column, a frontier line) not DERIVED from its detail is a second copy that rots: generate it, or update it in the same action as the detail.
- **Before creating any output item (file, folder, page, figure, record, rule): classify it on two axes FIRST.** LEVEL (rule-tier · instrument/register · round output · audience entry · record) fixes where it lives and who may write it; CONSUMER (machine · builder · audience) fixes language, vocabulary and WHICH artifact a gate reads — an embedded figure's artifact is its host page. Clauses: `rules/naming-and-placement.md`.
- **`[BC]` Four deliverable-shape rules — triggers here, mechanics in `ops/05-authority.md` §4a; a live boundary contract satisfies all four.** (1) A change that **cannot be statically verified** (a human must run/see it) ends with an unasked manual-acceptance checklist, ranked by CONSEQUENCE: `A 必驗` (≤7) then `B 體驗`. (2) A **baseline you doubt** goes behind a swappable interface only when the replacement is NAMED; a doubted *interpretation* names its isolation point instead. (3) A **deliverable that may not fit the round's budget/scope** declares its degradation order up front instead of shipping every part at 60%. (4) A **boundary/compatibility enumeration** is trimmed against known environment facts; anything kept because the environment is unknown is labelled a guess.
- **When fixing a reported defect** (bug, reviewer BLOCK, stale value): the object is the CLAIM, not the cited line — grep its keywords and number across everywhere it travels (headings, indexes, sibling artifacts, downstream docs) and settle every hit before calling it fixed (L-105). **If the code already passed user acceptance:** before editing, list the module's already-accepted behaviours; after the fix, re-check each and state none regressed — overwriting accepted design is a new bug. The same applies to changing a gate's severity ladder in EITHER direction — a deleted or promoted level removes coverage; ship it with a regression case reproducing what it used to catch.
- **When proposing extensions, refactors, or "next steps":** first state whether the core need is already met; if it is, recommend stopping. Never change for change's sake ("不要為了做而做").
- **Prior-art check — when a request would CREATE something new (a library / pipeline / rule system / asset store), or refers to past work or an established preference (之前・上次・做過・用過, "like before"):** consult the injected `[project-registry]` gist and any `[past_work_recall_inject]` candidates first, then ONE sweep — a source-only recall-sweep command (does not ship here; covers all memory silos, PROJECTS, lessons, xi, gsnap, digests) → the vault indexes (AssetVault = assets + `candidates/` shelf, the local Obsidian notes vault = notes) → a source-only past-session search tool (does not ship here). Report overlap and borrowable rules in one line BEFORE designing — or name what was checked. **Every vault** (any collection store: AssetVault, the local Obsidian notes vault, LexiconVault, knowledge packs) **is a shared, self-contained library** (user ruling 2026-10-06): what enters is a copy that stands without its origin; origin path@sha is provenance, never a dependency. A reusable thing not yet extracted is shelved as a copy in AssetVault `candidates/` (its `AGENTS.md` SHELVE task). Building a duplicate the registry already names is a miss, not initiative. **Third trigger — series continuation:** deliverable N of a series (第N份簡報/報告/規格) takes deliverables 1..N−1 + their review records as mandatory inputs; a compact/phase-log summary never counts as this check done (the verdict survives only as a NAMED consulted-list), and a single-source ruling covers only its named axis (`ops/lessons.md` L-039).
- **When a deliverable can fail at runtime** (rendering, resource loading, async init): failures must announce themselves — visible error notice or degraded fallback + structured console error; a silent blank screen is a defect. Name the likely failure modes and what the user would see in the delivery note. Animation/particle/realtime-render deliverables include a toggleable FPS/object-count readout.
- **When a deliverable includes an architecture/behavior diagram or view** (design doc, report, README, artifact): pick the representation by the question it answers — one question, one primary view, never one universal diagram; completeness claims ride on a state machine / decision table, never on a single view. Selection + blind-spot pairing: `skills/product-design-thinking/references/representation-models.md`.
- **Decision charter — when a decision point arises mid-task:** decide it yourself when it is (a) reversible, (b) not a values fork, (c) not a change to promised scope or UX semantics — and append it to the process ledger at that moment (`tools/process-ledger/ledger.py add`; a user ruling too, `--origin user`; a temporary scope cut names the event that lifts it). Ask ONLY for: irreversible/outward actions without standing authorization, values forks, scope/direction changes to a promise, UX-semantic changes, or an instruction contradicting an observed fact. Handing back a one-sane-answer decision is a miss, not caution. Every relaxation level. Full text: `ops/05-authority.md` §3.
- `[main]` **When starting a Tier-2 IMPLEMENTATION task at ops-relaxation L1/L2** (judged by what it will PRODUCE — a question that ends in code/figures/numbers counts, L-104): before any method/design work, emit a boundary contract — 5 sections, ≤18 lines (spec: `ops/05-authority.md` §4) — and record it, or a not-Tier-2 waiver, as one `boundary-contract` ledger row (`boundary_contract_notice.py` notices a first code write without one) — and re-check the deliverable against it at close-out. A live contract supersedes the four `[BC]` rules above. In plan mode the plan IS the contract carrier — don't gate twice.
- `[main]` **Premises & refutability — Tier-1+ deliveries, and session start when resuming:** surface the irreducible premises (tagged and origin-marked per `ops/05-authority.md` §4 line 0; resume = re-confirm recorded premises BEFORE acting) + a refutability statement at delivery (holds-when / overturned-by / evidence tier; Tier-1 → one line). Data + reasoning freely overturn MODEL conclusions; USER-origin premises change only via question + evidence, never auto-overturned. Spec: `ops/05-authority.md` §4, `30-judgment.md` R2.
- `[main]` **Depth-tier triage — when producing an analysis/design/evaluation answer:** pick a tier first. T0 (factual Q&A, mechanical edits, executing settled decisions) → answer directly. T1 (non-trivial claims) → tag each locally-verified/needs-search/user-decision, verify the load-bearing ones. T2 (≥2 of: design/plan/evaluation deliverable; hard-to-reverse; rests on volatile external facts; user says 深入/完整/評估/規劃/全面/加強) → two-pass protocol, `ops/30-judgment.md` R8. 「快答」forces T0; 「深想」forces T2. An active heavyweight skill (product-design-thinking, code-review-deep-checklist) takes precedence — never stack R8 on top. Unsure → lower tier + offer 「深想」; ask only when signals conflict (trivial-looking but irreversible).

## Project operations — applies only to multi-step or multi-agent project work

- **When handling a non-trivial project task** (dispatching subagents, batch operations, work spanning sessions): read `~/.claude/ops/OPS.md` first and follow its routing table — a rules layer subordinate to this file and project `CLAUDE.md` (higher layer wins on conflict). Layer/skill ownership boundaries: `~/.claude/ops/rules-usage-dict.md`.
- `[main]` **Relaxation gate — fires at the FIRST of:** first subagent dispatch of a project task; first ticket-ledger open; plan mode for a multi-phase task; an `[ops-health]` nudge reporting the level unset. **Standing rulings: Opus-tier main loop → L1, Fable-family → L2 — don't ask; state observed model identity + level. Invariants and hook-enforced rules never relax.** A recorded `ops-relaxation:` wins (project CLAUDE.md overrides); a cheap/mid-tier main loop skips the gate; anything else follows the ask procedure in `ops/05-authority.md` §2 — never self-relax, no answer → L0.
- `[main]` **When a prompt carries `[unattended-run]`**: the kickoff hook writes the run manifest and injects six obligations; scope and stop shape are hook-enforced (their deny/block text names the fix), the other four are yours, and the run is a BRANCH of the general ledger. The user's next untagged prompt ENDS the run, so a scope deny always means the user has not returned: name it as a blocker, never route around it. Spec + audit: `tools/process-ledger/README.md`.
- `[main]` **When closing out a session that made a commit, took a user ruling, or dispatched a subagent:** append one ≤8-line entry (did / rulings / deposits / next) to `references/<project>-session-digest.md` — a phase checkpoint or `D-NNN` written this session is cited by pointer/id, never restated. Spec: `references/session-digest-e9-design.md`.

## File hygiene — applies only when cleaning up, reorganizing, or writing report/doc files

- **When cleaning up or reorganizing a repo:** never delete — move obsolete files to `root/archive/` with a short note file; keep `archive/` out of git pushes (gitignore) unless told otherwise.
- **When producing a report/record document:** default to a NEW file; never overwrite a document the user may want for later post-mortems unless explicitly told to update in place.

## Language — applies to all conversations and file output

- **Chain of thought:** Always reason in English; preserve the AI's natural thinking process. Chinese rules do not apply here.
- **Conversation replies:** Final responses must be in Traditional Chinese. Technical/ambiguous terms take the English name inline: `中文名稱 (English name)`. **交付指向一律絕對路徑** — any file, folder or command a reply points at is written as an absolute path (keep the markdown link so it stays clickable). A label a reply coins (option, checklist item, test arm) has one meaning per conversation, never a token already naming something else.
- **File output — classify by PRIMARY CONSUMER, not by file type.** A `.md` file under `docs/` is not automatically a human document; ask who acts on it next.
  - *Human-read documents* (README, reports, retrospectives/experience guides, evidence & baseline records, post-mortems): Traditional Chinese; inline `中文名稱 (English name)` for technical terms.
  - *Machine-read content* (code, comments, commit messages, config files, prompts, `AGENTS.md`): entirely English. English by contract too: phase log + detail files (`workflow-checkpoint`), project context/glossary (`ops/60-bootstrap.md` §E), the `project-retrospective` CLAUDE.md snippet.
  - *Build specs an agent will execute* (PSM, 施工卡 / work cards, remediation plans — anything next dispatched to a session to implement): **English spec body**; Traditional Chinese (+ inline English) only for the sections the user personally rules on. *Concept-level design docs* (Concept Note, CIM, PIM + semantic contract): bilingual — Chinese where the user may intervene, English for glossary terms, IDs, schema/type and state names. Per-section lists + the keep-it-Chinese escape hatch: the rung table in `skills/product-design-thinking/SKILL.md` Phase 3 (canonical; binds outside the skill too).

## Compact Instructions

Applies to every compaction, auto or manual (pipeline documented in the source environment's own compaction-pipeline design note, not shipped here). Preserve verbatim, never paraphrase into "done": (1) project + phase status and the exact next step; (2) every decision taken with its reason; (3) file paths modified and their purpose; (4) user rulings and constraints still in force; (5) the prior-art / consulted list BY NAME — a gate survives compaction only as a named list, never as "already checked" (`ops/lessons.md` L-039); (6) open questions and pending user decisions. If a per-session handoff file exists (a source-only mechanism keyed by session id) it outranks this summary where they disagree. Drop: tool output, trial-and-error, superseded options. Language rules stay in force after compaction.
