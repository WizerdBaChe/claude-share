# 思考鏈拆解：從單場除錯到長線復活——遺留系統的認識論與戰役設計

- **日期**：2026-07-13
- **任務設定**：三段遞進的對話測試。第一段：把除錯方法從「散裝招式」上升到統一的哲學骨架；第二段：以實例施壓——「無人維護、文件失準、被縫縫補補的遺留系統，指令只有『讓它照原始設計語意活過來』」，要求展示啟動時的真實思考流程；第三段：追問長線規劃——贊助方自己也不知道該怎麼辦時，戰役 (campaign) 層級怎麼設計。

## 甲部：除錯的本體論——bug 不存在於程式碼裡

### 一、本體論翻轉

「bug」一詞有誤導性：它暗示 bug 是藏在程式碼某處的實體，除錯是「找到它」。但機器每一步都忠實執行了指令——程式碼沒有壞掉。真正壞掉的是：

> **腦中的系統模型，跟系統實際行為之間，出現了分歧 (divergence)。**

程式是心智模型的投影，症狀是投影與現實不符的證據。除錯的對象從來不是程式碼，是**除錯者自己的信念系統**。這個翻轉直接決定方法論的形狀：除錯是認識論 (epistemology) 問題——「如何系統性修正錯誤信念」——而人類文明對此只有一個成熟答案：科學方法。除錯不是「像」科學方法，它**就是**科學方法應用在一個奢侈的人造宇宙：實驗成本趨近零、完全決定論、且擁有原始碼。

### 二、唯一的迴圈

所有除錯技巧都是同一個迴圈某步驟的特化：

0. **界定分歧**——精確寫下「預期 X，觀察到 Y」。寫不出這句話就還沒開始除錯，只是在焦慮。X 與 Y 必須是可觀察事實，不是詮釋（「登入失敗」是詮釋；「POST /login 回傳 500」是事實）。
1. **具現化模型**——把腦中「系統應該怎麼運作」的因果鏈顯式攤開。多數人跳過這步，而它是樞紐：分歧必然藏在鏈上某個環節——模型在那個環節是錯的。
2. **找最脆弱的信念**——鏈上各環節信心不均等：有些是驗證過的事實，有些是「應該吧」。貝葉斯式 (Bayesian) 問法：*哪個信念若錯，最能解釋 Y？*
3. **設計判別性實驗 (discriminating experiment)**——標準不是「能否證明我對」，而是**「不管結果如何，都砍掉一半以上假說空間」**。假設為真與為假的預測必須不同，否則實驗是零資訊。
4. **執行、觀察、更新信念**——假說被推翻不是失敗，是假說空間縮小。回到 (2)。

**終止條件**由本體論給出：不是「症狀消失」，而是**模型能完整解釋為什麼之前壞、為什麼現在好**。缺前半句只是讓分歧暫時不可見。

### 三、招式的收編

| 散裝招式 | 在迴圈中的位置 |
|---|---|
| 重現 | 讓分歧成為可重複觀察的現象——認識論前提，不是規則 |
| 逐字讀錯誤訊息 | 步驟 (0)：觀察先於詮釋 |
| 事實與假設分離 | 步驟 (1)+(2)：標記因果鏈各環節信心水準 |
| 二分法 (bisection) | 步驟 (3) 的最優解之一：資訊熵最大化切割 |
| 一次改一個變數 | 保護實驗判別力；動兩個變數則無法歸因，退化為零資訊 |
| 修兩次沒好就停手 | 迴圈的後設監控：連續兩次高信心假說被推翻 → 錯的是整條因果鏈結構，重跑 (1) 而非在 (2)–(4) 打轉 |

### 四、情感姿態：否證主義

多數人除錯的隱含目標是**證明自己的程式碼是對的**（反覆檢查最有信心的部分），認識論上正確的姿態是**積極尋找自己是錯的證據**——波普爾 (Popper) 否證主義 (falsificationism)。最有信心的信念驗證起來最便宜但期望資訊量趨近零；該攻擊的是「應該吧」。

「卡關」的認識論定義：不是找不到 bug，而是**假說空間裡根本不包含真正病因**。唯一出路是承認步驟 (1) 的模型整個是錯的，去收集「認為不可能相關」區域的觀察——資深者卡關時讀文件、讀原始碼、印「不可能有問題」的中間值，不是在找答案，是在**擴充假說空間**。

> 一句話：**除錯是一場以自己的信念為對手的否證遊戲——輸得越快，修得越快。**

**可操作化方向**：除錯開場強制產出一行「預期 X／觀察 Y」與一條顯式因果鏈；每個實驗執行前先寫下兩種結果各自的含義；「同一 bug 第二次修不好」觸發強制重建因果鏈（與全域規則的 2nd-time 條目同源，此處給出其認識論依據）。

## 乙部：啟動思考——當「規格」本身是需要重建的失物

情境：無人維護、紀錄失準、被縫縫補補的系統；指令「用盡一切辦法讓它照原始設計語意正常作動，並重新記錄，讓專案活過來」。

### 一、第一個警報：指令裡有一個不存在的物件

「原始設計語意」在此情境**不是可取得的物件**——文件失準、程式被亂動、無人可問，它只是歷史上存在過、如今僅剩碎片證據的東西。第一個動作不是打開程式碼，是翻譯任務：

> 這是兩個專案：**(A) 考古——重建「原始語意」這份規格**；**(B) 對齊——讓程式符合重建出的規格**。

最大陷阱是 A、B 混做——邊讀邊「順手修」。規格重建完成前沒有判準分辨 bug 與 feature，此時動手每刀都是猜。

啟動時唯一值得停下來問的問題：**「正常作動」的驗收判準最終誰說了算？** 考古必然遇到證據不足的空洞，空洞需要有人拍板。

### 二、先固定現狀，再質疑現狀

在判定現有行為「錯誤」之前，先以特徵測試 (characterization tests) 把現有行為完整釘死——對所有還跑得動的入口記錄「餵 X、吐 Y」，不評判對錯，純錄影。理由：

1. 系統可能有下游依賴著「錯誤的」行為活著——某些「錯」已成為事實契約 (de facto contract)。
2. 之後每動一刀，這組測試就是地震儀：想改的行為應該變，沒想改的不准變。沒有它，整個工程是無防護攀岩。

核心原則：**在沒有可信規格的世界裡，「可重複觀察的現狀」是唯一不會說謊的東西。** 文件、註解、命名都會騙人，行為不會。

### 三、考古的證據信任等級

排序依據：「離『被迫誠實』有多近」。

1. **git 歷史**——最高級。讀的不是 code 是**演變**：初始 commit 最接近原始設計；每個縫補 commit 的 diff＋時間點都在說明*當時現實對系統施加了什麼壓力*。
2. **殘留測試**——寫下來的期望，曾被迫與程式對質，比文件誠實。
3. **資料結構與命名**——設計者世界觀的化石。一個 `settlement_batch` 表格勝過十頁文件。
4. **失準的文件**——不丟棄。它是「舊地圖」：與現地不符處正是最值得挖的地方，每處不符對應一次**沒被記錄的變更**——而沒被記錄的變更正是專案死因。
5. **程式碼註解**——最低級：連與程式對質的機會都沒有。

產出：**重建規格草稿**，每條標註證據來源與信心等級——「確定（git 初始 commit＋schema 一致）／推測（僅命名暗示）／空洞（無證據，需拍板）」。

### 四、補丁的三分類——全案最需要判斷力之處

重建規格 vs 釘死現狀的差異清單即工作清單，但每條差異先分類，分類決定動作：

| 類型 | 本質 | 動作 |
|---|---|---|
| 修復對原始語意的偏離 | 盟友 | 保留，並收編進新文件 |
| 回應原始設計沒料到的新現實（新 API／法規／規模） | **語意的演化**，非腐化 | 上浮裁決——「恢復原始語意」在此可能是錯的指令；方向問題不自行決定 |
| 治標止血（吞例外、hardcode 特例、繞過驗證） | 腐化 | 移除——但移除前必答：*它當初在止什麼血？* 血源大概率還在，直接拆止血帶等於重新放血 |

核心心法：**每個看起來愚蠢的補丁，都是某個真實壓力的化石。** 敵人不是寫補丁的人，是「壓力被回應了、但沒被記錄」。

### 五、改動紀律與「活過來」的定義

動手順序唯一原則：**每步結束時，「已驗證領土」只增不減。** 迴圈形狀：挑模組 → 對照規格 → 改 → 特徵測試確認「預期內變、預期外不變」→ **當場**寫語意文件 → 下一塊。文件在迴圈**裡面**而非最後補寫：此刻對該模組的理解是全案歷史最高水位，拖到最後水位已退。

「活過來」的驗收定義：專案死因不是程式壞，是**「理解」與「程式」的同步機制斷裂**——改動不再伴隨記錄，每次改動使下次理解更貴，貴到沒人付得起即棄坑。因此驗收標準為：**一個從沒接觸過此專案的人，能只靠新文件＋測試安全地做出下一次修改。** 跑起來是及格線，可持續被修改才是活著。交付三件套：對齊後的程式、有證據鏈的語意文件、特徵測試（由施工鷹架轉正為永久迴歸防線）。

**誠實標注**：第三、四步的邊界——「偏離還是演化」——在證據稀薄時本質是歷史詮釋而非工程，兩個同樣認真的人可能得出相反結論。方法論無法消除這種不確定性；它的全部價值是把「需要人拍板的判斷」從「可被證據決定的事實」中乾淨分離。

**可操作化方向**：遺留系統任務的啟動模板強制四產出——任務翻譯（考古／對齊分離聲明）、驗收判準歸屬確認、特徵測試優先於任何修改、證據分級的重建規格草稿。補丁處置一律過三分類表，「演化」類全部上浮。

## 丙部：戰役設計——當贊助方自己也不知道怎麼辦

### 一、長線的敵人不是技術，是預算耗盡

專案死於理解成本複利成長（[10](10-delegation-economics.md) 的成本視角）。長線計畫第一設計原則：

> **計畫必須經濟上可持續——持續產出可見價值養活自己，而非「投入六個月後一次交付」。**

大爆炸式重建（全懂→全修→一次交付）必死：(1) 無人知道全貌，估不出終點；(2) 中途零產出，贊助方耐心在看到成果前耗盡——這正是原始死因，不能用同一種病再殺它一次。長線規劃的形狀不是甘特圖，是**可無限跑、隨時可喊停、每圈留下淨資產的迴圈**。

### 二、第零階段：維生系統

挖任何東西前先建兩件基礎設施（它們是之後每圈成本的係數）：

1. **可重現的執行環境**——能否在乾淨機器上跑起來？若 build 依賴某台老機器的神秘狀態，第一優先是捕捉環境（容器化或逐步驗證過的重建手冊）。老機器一死，專案從「重病」變「死亡」。
2. **觀測能力**——最低限度 log／追蹤，讓「系統剛剛做了什麼」變成便宜可答的問題。

本階段紀律：**不修任何 bug**。低垂果實也不摘——尚無迴歸防線，每次「順手修」都是無保險裸改。

### 三、遠征迴圈 (expedition loop)

所有工作組織為固定節奏、有時間盒 (timebox) 的封閉單元：**選點 → 挖掘 → 固化 → 歸檔 → 重新評估**。

- **選點**：維護一張**領土地圖**，全系統分三色——已驗證（測試＋文件＋已懂）、可疑（跑得動但沒人懂）、黑暗（連跑不跑得動都不確定）。選點原則非線性推進，而是問：*哪塊黑暗領土若藏地雷，炸掉的東西最多？* 資料層、金流、對外契約優先於 UI。
- **挖掘**：乙部的考古＋對齊，限定在這一塊。時間盒到即停，不追擊。
- **固化**：靈魂步驟。遠征結束時該領土必須從可疑／黑暗變為已驗證——測試釘住、語意入文件、地圖上色。**絕不留挖一半的坑**：半開的坑其知識只存在短期記憶，而長線最大敵人是揮發性記憶——包括跨 session 間隔造成的那種。
- **歸檔**：三份持久文件每圈更新——**語意文件**（附證據等級）、**決策日誌**（每個偏離 vs 演化裁決、理由、拍板者——專案的免疫系統，防止三個月後自我推翻或重問已答之題）、**問題待辦**（需拍板的空洞）。
- **重新評估**：以新知識更新地圖。挖掘常改變地形認知（「這模組根本沒人在用」→ 大片黑暗直接圈禁，不挖）。

### 四、決策塑形：贊助方不知道怎麼辦，不是障礙，是分工設計

> **執行方把「大而模糊的方向問題」加工成「小而具體的裁決題」；贊助方只當否決者 (vetoer)，不當規劃者。**

具體做法：永遠帶**預設答案**來問。不是「這模組怎麼辦？」而是「證據顯示此補丁在回應 2019 年某外部 API 變更，我打算保留其語意並正規化實作，除非你知道我不知道的脈絡——N 天無意見即執行。」贊助方認知負擔從「想清楚」降到「聞有沒有怪味」。所有預設決策入決策日誌，可回溯、多可逆——[06](06-ask-vs-decide.md) 四變數模型（可逆性／變異數／資訊位置／爆炸半徑）的戰役級應用。真正需要「想清楚」的裁決攢批發問、控制頻率與大小：對沒把握的贊助方，一次丟二十個問題等於丟零個。

### 五、停損機制 (kill switch)：最不能省、最常被省

「讓它活過來」的未言前提是*它值得活過來*，而此事開工前不可判定。因此每 N 次遠征（約佔預期總量 15–20% 的節點）做**照價評估**：已驗證領土比例、每圈成本趨勢（升即壞消息——越挖越深而非越挖越懂）、以及關鍵一題：**「以現在所知，從零重寫核心語意的成本，是否已低於繼續考古？」**

答案翻轉的那刻，正確動作從修復切換為：把考古成果（重建的語意文件）當新系統的規格。此情境下前期工作**不是白費**——語意文件本就是兩條路共用的資產。這也是文件放在固化步驟內而非最後的深層理由：它把「中途轉向」的成本從災難降到可承受。

沉沒成本會說話且越後期嗓門越大，故停損檢查點必須**在情感投入發生前**寫進計畫並約定——這是對執行者自身判斷力的不信任設計，任何長線計畫都該有此防護欄。

### 六、複利符號的翻轉

> 單場除錯是「讓模型對齊現實」；長線復活是**「建造一台能持續便宜地做這件事的機器」**——每圈迴圈讓下一圈更便宜，而專案原本的死法是每次改動讓下次更貴。本質是把複利的符號從負翻正，然後讓它自己滾。

**誠實標注**：時間盒大小與停損節點密度兩參數無先驗正確值，只能以頭一、二圈實測校準。因此首次遠征刻意選**中等難度、端到端貫穿的縱切片 (vertical slice)**——同時是校準儀（量出真實成本係數）、概念驗證（迴圈在此專案轉得動）、與給贊助方的第一份可見產出。

**可操作化方向**：長線復活類任務的計畫模板強制五要件——維生系統先行聲明（環境可重現＋觀測）、三色領土地圖、遠征時間盒與「不留半開坑」紀律、三份持久文件（語意／決策日誌／待辦）、開工前寫死的停損檢查點與照價評估題。決策一律以「預設答案＋否決窗口」形式上浮。

## 三層合看的框架

| 層 | 問題形態 | 核心引擎 | 終止條件 |
