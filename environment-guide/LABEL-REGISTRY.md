# LABEL-REGISTRY — 本環境所有「可列舉標籤」的唯一定義表

> 造一個新的可列舉標籤(`Mode X`／`L2`／`Tier-3`／`R5`／新清單序號)之前,
> 先讀這裡。維護規則見 `ops/40-maintenance.md` §3 Birth budgets。
> 起因:`ops/lessons.md` L-008(hits 3)。
>
> **分享版說明（範本）**：這份檔以範本形式出貨。§1 判準與 §3–§6 的規則、維護段落與來源環境完全一致；
> §2 的家族表只留表頭與**一列**範例，已知碰撞只留**一則**範例——其餘列是來源環境自己累積的標籤，
> 不隨分享版出。採用者從自己的第一個撞名事件開始填：先跑 §5 的指令，再登記一列。

**治的病**:同一個標籤在不同地方指向不同東西,而引用時看不出來是哪個。

**總則**:**標籤必須自帶足以解析指涉的限定詞 —— 在每一個被引用的位置。**
限定軸有兩條,依標籤會不會「脫離擁有檔單獨旅行」而定。

---

## 1. 判準:這個標籤需不需要登記？

問一句:**它有沒有可能在不寫檔名的情況下被引用?**

| 情況 | 例 | 需登記 | 理由 |
|---|---|---|---|
| 文件內自指 | `§3`、`step 4`、`表 2` | ❌ 免 | 永遠是「本檔的」,不旅行;跨檔引用時一律寫成 `40-maintenance.md §3` |
| 幾乎都帶檔名 | `§`、文件內編號 | ⚠️ 建議 | 跨檔引用時補檔名即可 |
| **經常裸奔** | `Mode B`、`L2`、`Tier-2`、`AD3` | ✅ **必須** | 實測裸引用率 86–97%,且**撞過的家族全在這一列** |
| 專案內清單／回合 | `R5-1`、舊清單「第 5 項」 | ✅ **必須** | 見 §3,登記在專案 glossary 而非本表 |

**實測依據(2026-08-12)**:裸引用率 `Mode` 95%、`L0-2` 97%、`Tier` 86%,
`R` 40%、`§` 73%(`§` 天生文件內自指)。

⚠️ **這份實測有一個已知盲區,且已被推翻一次**:語料只涵蓋 `~/.claude/`,
**專案檔案不在內**。`R` 一度被判為「低風險」,實際上它是實務上撞最兇的家族
(見 §2)—— 因為碰撞發生在專案側,而專案側量不到。**低裸引用率只代表
環境內安全,不代表專案內安全。**

## 2. 環境層家族表(跨檔案旅行的標籤)

一個家族 = 一個軸 + 一個 owner。**owner 檔是唯一定義處,其餘皆為引用。**

| 家族 | 量的是什麼軸 | 方向／值域 | owner(唯一定義處) |
|---|---|---|---|
| `L0`／`L1`／`L2` | ops 鬆綁程度 | **L0 最嚴(預設) → L2 最鬆**(與業界 ASVS「數字越大越嚴」相反) | `ops/05-authority.md` §2 |

### ⚠️ 已知碰撞(未解決,登記在案)

（每則碰撞的形狀相同：標籤、哪幾個家族同時在用、引用規則。分享版只留下下面這一則作範例；
來源環境其餘已登記的碰撞不隨分享版出。）

**`R<數字>` — 環境層與專案層同時在用,這是實務上最常誤導的一個**:

| 用法 | 意思 | 出處 |
|---|---|---|
| `R1`–`R8` | 判斷準則(R2=何謂完成、R8=兩段式協定) | `ops/30-judgment.md` |
| `R9`、`R0`–`R7`… | **專案的測試回合** | 各專案(已知:Prism `R9`,見 `lessons.md`;另一專案 `R0`–`R7`) |

值域完全重疊,而且兩邊都習慣裸寫。
→ **專案回合一律加專案前綴:`PRISM-R9`、`<project>-R5`,禁止裸寫 `R5`。**
→ 環境層引用一律寫 `30-judgment.md R8`。

這一條的來源值得記:它**不是掃出來的,是使用者回報的**。環境內的裸引用率
量測把 `R` 判為低風險,因為碰撞全發生在量不到的專案側。

## 3. 專案層:清單與回合 ID(世代軸)

環境層靠 owner 檔區分;**專案層靠世代區分**,因為同一份清單會被新版取代,
而**舊版不會消失,它還被引用著**。這是 L-008 recurrence 3 的病。

五條,全部必守:

1. **不用裸序號,而且前綴要帶專案。** 會在段落外被引用的項目,ID 至少兩段:
   `<專案>-<世代>-<序號>`。`第 5 項` 不合格;`R5-1` **也不夠**——`R` 已被
   `ops/30-judgment.md` 佔用(見 §2 碰撞表),`PRISM-R5-1` 才合格。
2. **新世代不重用舊前綴。** 舊前綴凍結但保持有效,不回頭改寫。
3. **rank 要能從 token 看出來。** `R5`(回合)與 `R5-1`(項目)形狀不同 = 對;
   一個裸 `5` 同時可能是項目或回合 = 錯,這是最毒的一種。
4. **檔名帶世代。** `<project>-uat-r0-r7.md`,不是 `uat-list.md`。
5. **被取代的清單,檔頭掛狀態標記**,寫明繼任者與日期。

**ID 裡不要放檔名。** 追蹤性由登記列提供,不是塞進 ID:檔案會被改名、被拆、被
取代,把檔名編進 ID 等於讓 ID 隨改名一起壞掉。分工是——

| 要素 | 形式 | 為什麼 |
|---|---|---|
| ID(對話裡引用的) | `<專案>-<世代>-<序號>` | 短、穩定、跨改名存活 |
| 登記列(解析用) | 前綴 → **owner 檔** → 涵蓋範圍 → `[superseded:]` | 一次查詢就定位,檔名改了改這裡 |
| 引用慣例 | **在任何文件/對話中第一次提到時帶 owner 檔**,之後可裸寫 | 與 §2 的 Scale-label 限定詞規則同形 |

**登記處**:專案 glossary `references/<project>-context.md`
(`ops/60-bootstrap.md` §E),沿用既有的 `[superseded: <old>]` 欄位。
**不集中到本表** —— 本表只管環境層;專案前綴隨專案數成長,集中會腐爛,
而 §E 已經有活的維護掛載(`§A step 1` 每個 first session 讀、
`workflow-checkpoint` 每次 checkpoint 問)。

凍結的舊前綴**要留在 §E**,只記前綴與繼任者、不記內容 —— 因為你下次
讀到舊清單時,需要的正是「這個前綴是誰、被誰取代了」。

## 4. 檔名(2026-08-12 加入,實測驅動)

**一致性來自規則,不是來自模型習慣。** 實測 `references/`:有規則規定的四種
檔名 **8/8 完全遵守**;沒規則管的 5 個檔用了 **4 種不同寫法**
(`PROJECTS-`／`project-`／裸主題／日期後綴)。

1. **有規定就照規定**:`<project>-context.md`／`-decisions.md`／
   `-phase-log.md`／`-tickets.md`(`ops/60-bootstrap.md` §C/§E/§G、
   `workflow-checkpoint`)、`<project>-map.md`(§H 的 read-time 地圖;
   **機器產生,不手改**——與前四種相反的過期語意,不可混寫進同一個檔)。
2. **臨時文件**(規格、評估、UAT 清單、修繕案)用
   `<project>-<kind>[-<世代>].md`;`<kind>` 取自小字彙:
   `design`／`eval`／`spec`／`uat`／`remediation`／`report`。
   只有同 kind 存在兩份以上時才加世代。
3. **檔名不准造標籤。** 要嘛完整拼出來,要嘛用本表已登記的家族。
   反例(實例):來源環境一份評估文件的原檔名(該檔在其 `references/` 樹,不隨分享版出)把「層次 2/
   層次 3」壓成 `L2L3`,憑空造出 `L` 家族的第三種意思——而**本文從頭到尾
   沒有裸寫過 L2/L3**。縮寫發生在寫檔名的那一刻,那是規則看不到的地方,
   所以改用 sweep check 8 事後抓(`ops/references/integrity-sweep.md`)。
   **已於 2026-08-12 依本節改名**(範圍
   「層次 2/3」留在文件 H1 標題,不進檔名);check 8 現在回傳空集合。
4. **日期後綴只給「不會被取代的時點快照」**
   (`<topic>-evaluation-2026-07-29.md` 合格)。會出續集的東西用世代。

## 5. 造新標籤前的檢查(一個指令)

```git bash
cd ~/.claude && grep -rhoE "\bMode [A-Z]\b|\bL[0-9]\b|\bTier[- ][0-9]\b|\bAD[0-9]\b|\bR[0-9]\b|\bStage [0-9]\b|\bP[0-9]\b|\b[A-Z]{2,3}-[0-9]+\b" \
  skills/ ops/ references/ rules/ interop/ tools/ CLAUDE.md --include=*.md | sort -u
```
```powershell
cd $HOME\.claude; (Get-ChildItem skills,ops,references,rules,interop,tools -Filter *.md -Recurse) + (Get-Item CLAUDE.md) |
  Select-String -Pattern "\bMode [A-Z]\b|\bL[0-9]\b|\bTier[- ][0-9]\b|\bAD[0-9]\b|\bR[0-9]\b|\bStage [0-9]\b|\bP[0-9]\b|\b[A-Z]{2,3}-[0-9]+\b" -AllMatches |
  ForEach-Object { $_.Matches.Value } | Sort-Object -Unique
```

範圍註記(2026-09-01):原指令只掃 `skills/ ops/ CLAUDE.md`,而 Stage 撞名
(上表)就活在 `references/` 裡、由人工發現——掃不到違規住的地方的自查指令,
正是本檔要防的缺陷類。現已加 `references/ rules/ interop/ tools/` 與
`Stage [0-9]` 家族;輸出是標籤「值」的去重清單,多掃到生成檔只會多列值,無噪音成本。
2026-09-08 再加 `P[0-9]` 與泛型 `[A-Z]{2,3}-[0-9]+`(一次涵蓋 AP-/ES-/PH-/PL-/NM-/RD-/GO-/BC-/INV-
等連字號家族——紅隊審查指出:同一個 commit 登記的三個新家族,原本的掃描指令自己看不到)。

⚠️ 別用 `~/.claude/` 絕對路徑餵給從 PowerShell 叫起的 `bash -lc`——那個情境下
`~` 解析成 `/home/<user>`,指令會靜默失敗(實測 2026-08-12)。用上面的相對路徑版。
`--include=*.md` 是必要的,否則會命中 `__pycache__` 的 `.pyc`。

命中 → 三選一:**沿用該家族的既有語意** / **改用別的家族** /
**登記為新 owner 並在本表加一列**(同 commit,dict-sync corollary)。
「加一個意思但不登記」不在選項裡。

**這個 grep 看不到專案檔案。** 專案內的清單/回合前綴查 §E glossary,
以及本表 §2 的 `R` 碰撞表。

## 6. 這條規則管不到的事

**單位／實作漂移不歸本表管。** `40-maintenance.md` §3 曾寫「12K **chars**」
而 hook 實際量 `getsize`(**bytes**)—— 兩邊名字完全相同,漂掉的是單位。
那是「同一常數有兩個真相來源」,治法是**在兩處都註明單位 + 一條 drift
check**(§3「常數綁定」條 + `ops/references/integrity-sweep.md` check 7),
與命名無關。硬把兩者併成一條規則會讓兩種病都治不好。
