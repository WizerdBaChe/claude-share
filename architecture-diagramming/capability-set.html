問題：裝了這一組之後，哪個檔案決定哪件事？　宣告：四層＝理論／生產／稽核／執行，不是四顆 skill：生產與稽核共用同一份理論；虛線 = 「引用、不複寫」——理論只有一份，第二份就是會漂移的分叉；節點位置帶語意（同一層同一列）；邊為機器走線

問題：要一張新圖，資料依序經過什麼，哪一關會擋下來？　宣告：兩個 gate 是硬關卡：資料閘門擋「編造」，健全性檢查擋「不完整」；缺口不是繞過，是產物：缺口表與圖一起交付；交付＝圖＋圖例＋缺口表＋再生源，四件缺一不成立

問題：體檢一個既有系統時，圖是從哪裡來的、留下什麼？　宣告：重建視圖的來源是 code，不是既有文件——這是這條路的全部價值；用的是設計入口的同一支儀器，不是第二套檢查；留檔是為了下一輪 diff：一次體檢的產物是下一次的基準線

問題：一張圖要通過什麼才算「驗收過」？每一關失敗會退回哪裡？　宣告：三段驗證＝兩段機器＋一段人；人的那段不可由機器代簽；凍結後任何改動都重開 Step 5，收據重發（驗收過的位元組變了就不是那一份）；完整性由狀態機承擔：每個狀態的失敗邊都畫出來，不是只畫快樂路徑

問題：這 11 個檔案彼此怎麼依賴？「檢查器只有一份」長什麼樣子？　宣告：依賴讀自 import 敘述本身（node -e 逐檔掃過），不是讀 README 的描述；selfcheck.mjs 沒有任何人 import 它兩次——單一來源在圖上就是「只有一個箭頭進去」；vendor/ 只被 route.mjs 用；上游 rect 形狀在呼叫邊界轉接
